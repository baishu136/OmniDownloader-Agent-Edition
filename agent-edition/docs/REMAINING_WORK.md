## 1. P0：安全与部署边界

### R-01 远程 HTTP 管理接口缺少身份认证
- 现状：默认绑定 `127.0.0.1`；有 Host/Origin 白名单，但**没有令牌或用户认证**。
- 缺口：`--host 0.0.0.0` + `OMNI_AGENT_ALLOWED_HOSTS` 时，同网段任何人都能调用管理接口与 MCP。
- 影响：远程部署即完全暴露；Host/Origin 不能替代身份认证。
- 建议：增加 `OMNI_AGENT_ADMIN_TOKEN`（启动生成/用户设置），除本机回环外的请求强制 `Authorization: Bearer`；MCP HTTP 同样校验；保留本机免令牌体验。
- 验收：本机免令牌可用；非回环无令牌 401；携带令牌可调用全部管理接口；测试覆盖 Host/Origin 与令牌组合。
- 涉及：`api.py`（中间件）、`__main__.py`、`OPERATIONS.md`。
- 风险：改变远程部署方式，需要文档与迁移说明。

### R-02 Docker 镜像未验证
- 现状：`Dockerfile`、`docker-compose.yml`、CI 工作流存在；本机未安装 Docker。
- 缺口：本轮新增设置/路由未在容器内构建与启动验证。
- 验收：`docker compose up -d --build` 成功；`/api/admin/status` 与 MCP HTTP 握手通过；只读根文件系统与非 root 用户可运行。
- 阻塞：本机无 Docker；需在有 Docker 的环境执行。

### R-03 真实平台与机器人验收
- 现状：全部测试为模拟 HTTP/本地受控服务。
- 缺口：未用真实 QQ / Telegram / AstrBot / 平台账号验证。
- 验收：真实下载 → 交付 → 回执 → 清理全链路；失败注入（断网、限流、超时）后的恢复。
- 阻塞：无授权账号与机器人。

## 2. P1：下载体验闭环

### R-04 暂停 / 继续与断点续传
- 现状：仅取消、重试；核心 `TaskManager` 不支持断点续传。
- 缺口：不能提供真正的暂停/继续；状态机无 `PAUSED`。
- 建议：先做“暂停排队任务”（不启动）与“取消保留临时文件”，再评估核心断点能力；不得把重新下载冒充续传。
- 验收：暂停后不消耗带宽；继续时行为明确标注“重新下载”或“续传”。
- 依赖：`windows/core/task_manager.py` 能力评估。

### R-05 字节级进度与可靠 ETA
- 现状：核心只上报百分比与速度文本；`visual_events` 不含字节数。
- 缺口：无法展示已下载/总字节；ETA 只能来自核心文本。
- 建议：扩展核心 `on_progress` 增加 `downloaded/total`（需同步 Windows GUI 兼容），或在 worker 解析 yt-dlp hook 后写入事件；仅在总量已知时展示 ETA。
- 验收：大文件与缓存命中场景下字节数单调、完成时等于文件大小。
- 风险：改动共享核心影响 GUI，需要双端回归。

### R-06 机器人端多链接自动拆分
- 现状：服务端 `extract_chat_links` 已能识别多链接与指令；AstrBot 插件与 Bot 示例仍按单链接处理。
- 缺口：一条消息含多个链接时需要机器人端逐个提交。
- 建议：在插件中调用 `extract_chat_links`（或新增内部接口）逐个处理，保持审批与去重语义。
- 验收：一条消息两个链接生成两个任务；重复链接只提交一次；失败互不影响。
- 涉及：`examples/astrbot_plugin/main.py`、`examples/bot_client.py`。

### R-07 交付逐文件继续发送
- 现状：`receipts` 已保证重试跳过已确认文件；`public_delivery.files` 提供 `sent` 标记。
- 缺口：没有“只继续发送未完成文件”的显式 API/按钮；`UNCERTAIN` 仍要求人工核对。
- 建议：增加管理端 `POST /api/admin/deliveries/{id}/resume`（仅当无 `UNCERTAIN` 文件）或前端按钮复用 `retry` 并提示。
- 验收：10 个文件成功 6 个后重试只发送剩余 4 个；不会重发已确认文件。
- 风险：`UNCERTAIN` 语义必须保持，不得自动重发。

### R-08 缓存清理预览的完整信息
- 现状：`cleanup_preview` 返回文件数与字节数。
- 缺口：未标记“内容已变化”的文件（实际清理会以 `FILE_CHANGED` 中止）；未提供按任务维度预览。
- 建议：预览时校验摘要并标注 `changed`，让用户在清理前处理。
- 验收：篡改文件在预览中显示为不可清理；实际清理不会误删。

### R-09 画质/编码偏好
- 现状：支持最高画质、指定高度、容器、音频格式；返回实际宽高与是否有音轨。
- 缺口：HDR 偏好、视频/音频编码偏好、帧率约束未作为可配置意图传入核心。
- 验收：请求的编码/HDR 不被承诺为源不存在的值；返回实际容器与尺寸。

## 3. P1/P2：管理界面

### R-10 首次启动向导前端
- 现状：`GET/POST /api/admin/onboarding` 已可用，已有配置不算新用户。
- 缺口：管理页没有向导、没有“跳过”和“完成后不再提示”的 UI。
- 验收：新数据目录首次打开显示 4–6 步（目录/代理/Bot/Cookie/MCP），每步可跳过；已有配置不显示；完成后刷新不再出现。

### R-11 任务管理页完善
- 现状：“最近任务”列表（20 条）+ 可恢复失败重试。
- 缺口：历史分页/筛选、批量取消、打开文件所在目录（仅本机）、交付明细展开、脱敏错误详情弹窗。
- 验收：能按状态筛选、取消排队任务、查看文件与回执；不引入媒体播放器。

### R-12 诊断页与报告导出
- 现状：`GET /api/admin/diagnostics` 返回结构化检查。
- 缺口：管理页无入口；没有“下载脱敏诊断报告”按钮。
- 验收：页面显示每项 ok/warn/fail；导出 JSON 不含 Cookie、Token、绝对路径。

### R-13 新增设置项的前端入口
- 现状：`task_retries`、`retry_base_seconds`、`max_active_per_owner`、`max_jobs_per_owner_per_day` 只能通过 API/MCP 修改。
- 缺口：设置页没有对应输入；`cleanup/preview` 与配置导入导出没有按钮。
- 验收：页面可编辑并即时保存，范围校验与后端一致。

## 4. P2：Agent 与配额

### R-14 MCP 调用收敛
- 现状：工具仍为 23 个，任务结果含 `next_action`。
- 缺口：典型流程仍需 `download_media` → `get_task_status` 轮询；缺少“等待并返回最终结果”的一体化参数。
- 建议：评估在现有工具上增加可选 `wait_seconds`（不新增工具），复用长轮询。
- 验收：一次调用即可拿到完成态；旧客户端不受影响。

### R-15 群组级配额与频率限流
- 现状：按 `owner` 的并发/每日配额。
- 缺口：群组与私聊未区分配额；没有每分钟请求限流。
- 建议：`owner` 由桥接传入群标识时可复用；另加 `max_jobs_per_owner_per_minute`。
- 验收：突发刷屏被限流且返回 `RATE_LIMITED`（可重试）。

### R-16 敏感数据备份
- 现状：配置导出不含凭据（正确）。
- 缺口：没有 Cookie / Bot Token / 浏览器 Profile 的加密备份/迁移工具。
- 建议：提供显式、带口令的加密备份；默认不导出，恢复需二次确认。

## 5. 质量与性能

### R-17 性能与资源
- 未做：长时间运行内存、文件句柄、SQLite 锁竞争、大文件发送内存、并发调度、进度通知频率。
- 建议：用 24h 压测 + 1000 次小任务 + 单 4GB 文件三类场景；为清理与大文件路径增加基准。
- 验收：内存稳定、无句柄泄漏、WAL 不无限增长；大文件发送不整文件读入内存。

### R-18 安全回归补全
- 现有：SSRF（含 Fake-IP/TUN）、受控目录、路径穿越、符号链接、URL/凭据/路径脱敏。
- 缺口：ZIP 内容安全（解压炸弹/相对路径）、远程鉴权（R-01）、Bot Token 日志审计、重定向全链路测试。
- 验收：新增用例覆盖上述场景；任何删除操作限定在受控目录。

### R-19 迁移与故障注入
- 现状：SQLite 自动补列、配置导入备份。
- 缺口：旧版本账本/设置的真实升级演练；断电/写满/数据库锁冲突注入测试。
- 验收：升级前后任务可读；写入失败不产生半成品记录。

### R-20 版本与发布
- 现状：代码在 `codex/stability-sprint01`，版本仍为 `0.2.0`。
- 缺口：未升版本、未写 CHANGELOG、未重新打 tag、未更新 README 的功能概览截图。
- 建议：合并后升 `0.2.1`（或 `0.3.0`），生成新 ZIP 与 SHA-256，更新 Release 说明。
